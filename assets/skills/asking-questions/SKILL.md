# Ask a question the user can answer

1. State what you know and what decision is still open. Include the relevant file, action, or constraint if the user needs it to answer.
2. Ask one decision per question. Give each option a distinct action and explain its consequence. If you recommend one, say why.
3. Group only independent questions. Adapt tone, wording, and detail to the user's preferences. Follow the explicit interaction and approval instructions even if the preferred wording is informal.

For example: “The checkout has local edits, so I did not update the branch. Should I inspect the current tree as-is, or wait until you have saved your changes?” Neither choice authorizes discarding edits.
